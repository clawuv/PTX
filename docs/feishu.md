# 手机飞书接入

PTX 使用飞书企业自建应用机器人的长连接。手机向机器人发任务，电脑本地执行；无需公网 IP、端口映射或 Webhook 服务。电脑必须保持联网且 PTX 正在运行，休眠或退出后无法接收任务。同一应用只连接一台电脑，飞书会在多连接之间分配事件，不会广播。

## 扫码绑定（推荐）

1. 点击设置中的「手机 · 飞书」，未绑定时自动弹出二维码；关闭后也可点击「扫描绑定」重新打开。
2. 用手机飞书扫描弹窗二维码，在飞书页面确认创建新应用及权限。
3. PTX 自动接收应用信息与扫码账号，选择执行引擎、项目和模型后点击「保存绑定」。密钥不会显示在界面中。
4. 点击「连接飞书」，向新机器人发送 `/帮助` 验证收发，再直接发送普通文字。

二维码过期可重新生成，取消会停止本次绑定。仅创建新应用，不更改已有机器人。飞书可能要求管理员授权；自动预填权限和订阅受平台开放范围影响，创建成功不代表消息已经连通。如果收不到消息，按照下方检查清单核对事件、权限和发布状态。

## 平台侧检查清单

扫码创建的应用收不到消息时，在飞书开放平台逐项核对：

1. 应用已启用机器人。
2. 已添加接收机器人单聊消息权限 `im:message.p2p_msg:readonly` 、以应用身份发消息权限 `im:message:send_as_bot` 和卡片权限 `cardkit:card:write`。已有应用新增权限后须重新发布版本。
3. 在飞书事件与回调中已选择长连接接收事件，订阅 `im.message.receive_v1`。
4. 应用已保存版本并发布到所在企业，扫码账号在应用可用范围内。
5. 允许使用的账号使用该应用下的 Open ID（`ou_` 开头）；不要使用其他应用下的 Open ID。

设置页不提供手动填写 App ID、密钥和 Open ID 的入口，配置统一通过扫码绑定获取并加密保存。

开启连接表示允许指定账号向所选本地项目下发 AI 开发任务，并通过飞书接收任务状态和助手流式回复。回复可能包含项目内容。App Secret 仅存于主进程，通过操作系统安全存储加密，不回传界面。没有可用安全存储时拒绝持久保存。

## 持续会话

普通文字会进入当前绑定会话；没有会话时创建名为「飞书会话」的电脑端会话。手机和电脑使用同一引擎会话和只读 JSONL 上下文。运行时收到新消息使用引擎 follow-up 队列，停止会关闭该运行时并丢弃未执行队列，之后发消息恢复原会话。

- `/新建` 或 `/new`：开始新会话，使用桌面绑定的项目、引擎和默认模型。
- `/会话` 或 `/sessions`：显示当前授权项目的最近 20 个非归档会话及完整 ID。
- `/切换 会话ID` 或 `/switch ID`：继续该项目已有会话；保留其模型和上下文，不覆盖为绑定默认模型。
- `/状态`、`/结果`、`/停止`：查看当前会话、读取最后文字回复或停止。
- `/任务 目标` 作为普通消息的兼容写法，不再生成独立任务记录。
- `/帮助`：命令说明。其他未知斜杠命令也显示帮助。

当前会话运行中不允许切换，先等待或停止。桌面在绑定会话产生的助手文字回复也会同步到飞书；切换时不重放旧回复。断线重连和应用重启保留会话绑定及回复回执，未确认提交的消息不自动重发。应用退出前尚未执行的引擎队列不会由 PTX 重放。仅支持指定账号单聊文字，不接受群聊或附件。任务总览和验收功能仍可在桌面使用，不再是手机聊天必经步骤。

## 验证要求

自动测试覆盖身份、单聊、时间窗口、重复投递、配置边界和任务路由。上线前仍需在真实飞书租户中验证机器人权限、消息接收、任务执行、结果回传、断线重连及重启恢复。没有真实应用凭据时不能把模拟测试当作飞书端到端验证。

## 本地验证记录

2026-10-17，macOS arm64、Node 24.15.0 / npm 12.0.2：相关后端、任务、IPC、preload 和设置测试通过；Electron 测试验证手机入口、未配置时禁止连接，且设置页无手动密钥输入入口（扫码绑定按钮位于标题右侧）。生产依赖审计通过，无 high / critical 报告。真实租户联调尚未执行。

飞书服务、加密持久化、消息校验和 IPC 接入使主进程 bundle 达到 510,140 字节；按体积规则将主进程预算从 496 KiB 调为下一档 504 KiB。SDK 保持外部生产依赖，不进入 renderer。

扫码接口验证：已从官方 `registerApp` 获取有效的 HTTPS 授权链接，域名为 open.feishu.cn；获取后立即取消，没有创建应用。扫码确认及应用创建后的真实收发仍待用户联调。

持续会话新增目录校验、恢复与回复同步，主进程测量为 519,494 字节，按规则将预算调整为下一档 512 KiB。

`/新建` 会将已授权运行实例的空会话登记到桌面目录，并发送目录变更通知，因此无需先发送任务就能在侧栏打开“飞书会话”。空会话读取返回空消息列表；第一条消息由引擎写入磁盘后，目录使用正式记录，不产生第二个条目。此登记仅保存在内存中，运行实例退出后移除。没有发送过消息的空会话不保证跨应用重启保留。

## 流式卡片

助手回复使用 Card JSON 2.0 和 CardKit。创建实体后通过 interactive 消息发送 card_id，正文按秒合并后调用文本流式更新接口；结束时关闭 streaming_mode，再写入最终卡片。工具调用只展示默认折叠的名称与执行状态摘要，不发送参数、完整工具输出或思考内容。控制命令回执同样使用 JSON 2.0 卡片。

卡片 ID、发送 UUID 和递增 sequence 存入现有加密绑定记录，失败后重试同一卡片，最终更新成功后才记录回复已送达。正文上限为 8,000 个 Unicode 字符，超出时提示在电脑查看完整回复；工具摘要最多 50 项。卡片实体创建成功但本地保存失败可能留下未发送实体，不会重放原始任务。真实飞书/Lark 客户端中的卡片渲染仍需租户联调确认；当前扫码和连接使用飞书域名。

此次流式卡片、回执恢复和事件摘要使主进程 bundle 达到 530,439 字节，按体积规则将预算调整为下一档 520 KiB；未引入额外依赖。
