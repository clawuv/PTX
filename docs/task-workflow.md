# 本地任务工作流

任务页帮助开发者在多个项目之间安排工作，并在执行后检查结果。当前为免费本地预览，尚未开放购买。现有聊天、模型、附件、项目、Git、浏览器、调度和会话能力不受影响。

## 使用

1. 在侧栏打开「任务」，点击「新建任务」。
2. 选择项目和引擎，填写任务名称、目标和验收要求。已有模板可以复用目标和要求。
3. 选择项目中已授权的目录。并行修改代码时，勾选创建独立 worktree，输入新分支，使用系统对话框选择位置。创建成功后会切换到该 worktree 项目。取消表单不会删除它。
4. 明确选择模型及其支持的推理强度，保存后再启动。模型可用性由现有运行时重新验证。
5. 执行中需要答复问题或授权时打开关联会话。可停止任务，停止后状态为失败，保留会话供检查。
6. 执行结束进入「待验收」。查看当前工作区变更、模型回复、实际工具调用和工具输出。可以保存修改要求后重新启动，也可以手动标记已验收。
7. 用状态、项目或关键词筛选跨项目列表。任务详情可以保存为模板，创建表单中可以删除不再需要的模板。

状态为：待开始、运行中、待确认、待验收、失败、已验收。AI 声称完成不等于通过验收，工具调用没有报错也不等于测试或业务要求通过。

## 数据与边界

- 任务和模板保存到 Electron userData 下的 `development-tasks.json`。文件使用私有权限、临时文件写入和原子替换；写入前做版本与大小验证。
- 元数据包括项目、引擎、工作目录、目标、验收要求、选择的模型、会话引用和状态历史。没有新增网络上传、遥测或购买接口。
- 继续使用现有项目授权、Pi/OMP RPC、模型验证、会话目录和 Git 接口。任务服务不写入会话 JSONL，也不读取模型账户凭证。
- 会话正文按需只读加载，不复制到任务文件。不同任务不会自动共享代码或提示词。跨引擎打开会话时，等待目标引擎的项目加载后再激活会话。
- Git 部分是读取时的工作区快照。共享目录里的其他修改可能包含在内；已提交修改不在这个列表里。不能把它当成任务专属或冻结的变更报告。工具记录也来自关联会话，重试保留此前记录。
- 证据读取失败会显示错误，界面不会把空白证据当作验证成功。人仍需根据验收要求判断，不自动认证测试通过。
- 同目录或父子目录的任务不并行启动；已有执行中的聊天运行时也会阻止同目录任务启动。不同 Git worktree 可以并行。此限制不替代操作系统级文件锁，也不能限制外部编辑器或终端。
- 重试使用原会话，先重新检查项目授权和会话归属。失败可能已有文件修改，启动前应检查已有结果。
- 应用重启将未结束的运行中/待确认任务标为失败并解释中断，不自动重跑。电脑关闭或休眠不保证执行。
- 当前保留最多 500 条任务、100 个模板，每条最多 200 次状态变更，存储上限 16 MiB。达到上限时明确报错；后续可根据试用反馈增加归档导出。
- 损坏或未知版本的任务文件会保留原样，并仅在任务功能报告加载失败。不会用空记录覆盖，也不会阻止免费聊天功能启动。

## 实现与验证

- 主进程：`electron/main/tasks/service.ts`。
- 固定 IPC：`tasks:*`，沿用主窗口来源验证；preload 只暴露类型化的方法。
- 渲染层：`TasksPage`、`TaskForm`、`TaskDetail`，沿用主题变量与中英文目录。
- 单元与前端验证：`npx vitest run tests/backend/tasks.test.ts tests/backend/preload-contract.test.ts tests/frontend/tasks-page.test.tsx`。
- 真正的 Electron UI 流程：先 `npm run build`，再 `npx playwright test tests/e2e/app.spec.ts -g 'creates a task'`。测试使用隔离的项目、用户目录和 CLI fixture，不使用真实模型账户，不证明任意供应商的模型质量或图片能力。

商业化验证、定价假设和发布前置事项见 [验证手册](business/validation-playbook.md)。
